第一章 认知准备：CC 为什么强

1.1 LLM Loop（大模型循环）

CC 是一个以大模型为大脑的 agent 程序，运作方式如下：

  1. 用户输入提示词
  2. 程序把提示词 + 工具说明书一起发给大模型
  3. 大模型决定下一步用什么工具，并输出工具调用指令
  4. 程序按指令执行工具（读写文件、跑命令、调 API）
  5. 把执行结果返回给大模型
  6. 大模型基于结果决定下一步，循环 2–5 直到任务完成
  7. 程序把最终结果返回给用户

1.2 Harness（脚手架工程）

Harness 指 agent 程序中除大模型之外的所有设计——上下文管理、工具调度、权限系统、回滚机制等。同一个大模型，搭配不同 harness，效果差异巨大。CC 是当前 harness 工程的集大成者。

1.3 CC 能做什么

不止编程：写文案、查资料、整理数据、做表格、做报告、操作飞书、发公众号、调研社交媒体、生成图片等知识工作均可。

第二章 安装与模型配置

2.1 前置准备

  1. 下载并安装 Cursor（或 Trae、Windsurf 等 agent IDE）
  2. 新建本地文件夹 first-cc，用 Cursor 打开
  3. 调出 Cursor 内置终端

2.2 安装 CC（两选一）

方式 A：官方一行命令

  1. 复制 CC 官网安装命令，粘贴到 Cursor 终端回车
  2. 输入 claude --version，出现版本号即成功

方式 B：让 IDE Agent 帮装

  1. 在 Cursor agent 框输入：帮我安装 Claude Code，处理依赖与网络问题
  2. 等待自动完成后用 claude --version 验证

2.3 配置模型 API（CC switch）

  1. 下载并安装 CC switch 工具
  2. 必须在启动 CC 之前完成配置，否则 CC 默认走官方登录
  3. 填写：API Key、Base URL、自定义模型名（高/中/低三档）
  4. 保存后即可在 CC 内通过 /model 切换

2.4 启动 CC

  1. 终端输入 claude 回车
  2. 选择主题色 → 安全提示选 yes → 文件夹可信选 yes

2.5 全自动权限启动（无任何确认）

claude --dangerously-skip-permissions

后续在终端按上方向键可快速复用该命令。

第三章 三种权限模式

模式文件修改终端命令进入方式
计划模式 Plan Mode先出方案再执行先出方案再执行默认或 shift+tab
默认模式 Default智能判断，需要时询问需要时询问shift+tab
自动编辑模式 Auto-Edit直接修改不询问仍需询问shift+tab

计划模式下的四个选项：

  1. 同意方案 + 切自动编辑模式
  2. 同意方案 + 保持默认模式
  3. 不同意，继续讨论
  4. 按 shift+tab 提交反馈意见

终端命令确认时的三个选项：

  1. yes：仅本次同意
  2. 本项目后续同类命令不再询问
  3. 拒绝并重新讨论

第四章 四种核心交互方式

4.1 文字指令

换行键：macOS option + 回车，Windows Ctrl + 回车。不要按 shift + 回车，会直接发送。

指令越具体越省 token。短指令会让 CC 花大量 token 通过 grep 探索本地文件。

4.2 @文件 / @文件夹

@main.js 解释代码逻辑并加中文详细注释

长提示词建议先写到本地 .md 文档里，再用 @文档名 引用。

4.3 图片

  • 拖拽图片到对话框
  • 或 Ctrl + V 粘贴（macOS 也是 Ctrl+V，不是 Cmd+V）

4.4 Bash Mode（! 命令）

对话框最前面输入 !，进入系统命令模式：

!npm start
!ls -la
!git status

长进程后按 Ctrl + B 转入后台，避免阻塞 CC 对话。

第六章 回滚与版本管理

6.1 CC 自带快速回滚

  • 快捷键：连按 两次 ESC
  • 命令：/rewind
  • 选项：仅回滚对话 / 回滚对话+文件 / 仅回滚文件 / 取消
  • ⚠️ 局限：只能撤销 CC 编辑的文件，无法撤销已执行的终端命令

6.2 Git 版本管理（真正的后悔药）

用自然语言让 CC 完成全流程：

  1. 帮我安装 Git 并绑定我的 GitHub 账号
  2. 把当前项目初始化为 Git 仓库并提交首个版本
  3. 把当前分支推送到 GitHub 远程仓库
  4. 帮我回滚到上一个稳定版本

习惯建议：每完成一个小功能，让 CC 存一次档。

第七章 上下文管理

7.1 三个核心命令

/compact    主动压缩，保留关键信息
/clear      彻底清空，等同新开对话
/context    查看 MCP / Skill / 历史对话各自占的 token

CC 会在快满时自动压缩，但任务切换时建议手动 /compact。

7.2 实时显示上下文占比

让 CC 开启 statusline，重启终端后底部一直显示百分比。经验阈值：超过 60% 就该 /compact。

7.3 恢复历史对话

  • 进 CC 后输入 /resume
  • 或启动时直接 claude -c

第八章 三层记忆机制

8.1 第一优先级：claude.md

层级路径作用范围适合写什么
全局~/.claude/CLAUDE.md所有项目个人偏好
项目级项目根 CLAUDE.md当前项目技术栈、架构、规范
文件夹级子文件夹 CLAUDE.md该文件夹内局部特殊规则

项目有雏形后运行 /init 自动生成；用 /memory 编辑。

Karpathy 的著名 skill 仅几百行通用规则，已 5 万 GitHub stars——claude.md 不是越长越好，应只放顶层不变原则。

8.2 第二优先级：Auto Memory

  • 开启：/memory → Auto Memory → on
  • 记录：用户偏好 / 反馈纠错 / 项目决策 / 外部资源索引
  • 存储：.claude/projects/<项目>/memory/
  • 仅 MEMORY.md 索引被默认加载，详细内容按需加载
  • 纠错：忘掉刚刚关于 XX 的记忆
  • 仅作用于当前项目，换项目需重新积累

8.3 第三优先级：自定义规范文档

在 claude.md 里写：

当修改前端视觉时，参考 品牌视觉规范.md
当撰写产品文案时，参考 文案语气规范.md

第九章 高级拓展功能

9.1 Skill（技能）

类型例子
知识型页面设计规范手册、品牌视觉指南
流程型财务记账报销流程、合同审批 SOP
工具型调用 nano banana 生成图片、调用 ffmpeg 压缩视频
混合型公众号自动排版+发布、调研报告生成+推送
  • 全局安装：~/.claude/skills/
  • 项目级：项目根/.claude/skills/
  • 智能安装：先装 find-skill，让 CC 自动找并装
  • 调用：自动 / /技能名 / 提示词点名
  • Skill 多 + 上下文紧张时务必在提示词中点名

9.2 MCP 与 CLI

MCP：AI 与外部服务的转接头，单个占 token 较多，不适合堆量。
演进：轻量服务转 Skill，重量服务转 CLI。

CLI 工具用途
飞书 CLI文档、多维表格、邮件、日历
OpenSale抓取小红书、微博等社交内容
GitHub CLI仓库、PR、Issue 操作

9.3 Sub-Agent（子代理）

隔离上下文 + 并行执行。创建：自动派生 / /agent 手动创建。

9.4 Hook（条件触发器）

帮我配置 Hook：每次 CC 完成任务后播放提示音并发送系统推送
帮我配置 Hook：每次提交代码前自动运行 ESLint 检查

9.5 Plugin（插件）

插件 = Skill / Sub-Agent / Hook / MCP 的打包整合。/plugin 进入管理页 → Discover → 选范围 → 安装。

第十章 实操案例：30 分钟做一个 Electron 番茄钟

  1. 启动 CC：claude --dangerously-skip-permissions
  2. 输入：做一个桌面番茄钟软件，技术栈用 Electron
  3. CC 反问 → 选第一个预设方案
  4. 计划模式查看方案 → 选"同意+切自动编辑"
  5. npm 安装时选"本项目不再询问"
  6. 运行：新开终端 npm start 或原终端 !npm start
  7. 转后台：Ctrl + B
  8. 拖配色参考图进对话框，"按这张图改主题色"
  9. /simplify 三角度审核优化
  10. 帮我提交当前版本到 Git，并推送到 GitHub

第十一章 新手避坑速记

  1. 指令越具体，CC 烧的 token 越少、执行越准
  2. 上下文超 60% 立即 /compact
  3. 重要项目必须 Git 存档，CC 自带回滚撤不了终端命令
  4. 自动记忆只在当前项目生效
  5. Skill 多时建议在提示词中点名调用
  6. macOS 粘贴图片用 Ctrl+V 而非 Cmd+V
  7. 短指令未必省事，详细描述往往更省 token
